# Jenkins 与 Docker 发布

唯一入口是仓库根 Jenkinsfile；执行 deploy/jenkins-build.sh。构建环境使用 jdk8（真实 Java 1.8）和 maven3（Maven 3.9），Jenkins 自身继续使用 Java 21。

## 生产配置

根据 .env.example 准备环境文件，在 Jenkins Credentials 新建 Secret file，ID 必须为 cy-user-prod-env。数据库和 Redis 使用已有实例及独立账号，Compose 只管理本应用，不创建或删除数据库容器/数据卷。生产文件不提交 Git。更新服务器保存的文件不会自动更新 Jenkins 凭据，需在凭据页面替换文件再构建。

服务别名 user-api，端口仅绑定服务器回环地址 18731；网络为 cy-pregnancy-internal，可用 SERVICE_NETWORK 环境变量调整。两个服务的 ADMIN_READ_KEY、CONTENT_READ_KEY 分别对应一致，JWT 密钥独立。微信配置作为 WX_APP_ID、WX_APP_SECRET 注入；配置存在不等于微信 code 交换已验证。

## push 自动发布

Pipeline script from SCM 使用对应 GitHub 仓库及 SSH 凭据，分支固定 */main，Script Path 为 Jenkinsfile。代码中已声明 githubPush()。GitHub 仓库 Settings → Webhooks 配置 Jenkins 地址加 /github-webhook/，Content type 为 application/json，仅选择 push，启用 Active。首次手动构建注册触发器后，再 push main 验证。

流程：拉代码 → mvn clean verify → Dockerfile 打包 JAR → Compose 更新应用 → 健康等待。镜像使用构建编号。每个应用只由一个任务发布；不同 Java 任务应错开推送，避免当前小内存服务器同时编译。单任务禁止并发不等于两个任务互斥。

## 验收与恢复

~~~bash
curl --fail http://127.0.0.1:18731/actuator/health
docker ps --filter name=user-api
~~~

验证能力接口、知识只读链路；微信真实登录须使用本次新获取的 code。公网入口由宝塔 HTTPS 代理，不开放内部接口、健康细节或数据库。

失败时脚本尝试恢复旧镜像；回退镜像不撤销数据库迁移。不要清理当前及上一版镜像，不运行 down -v 或全局卷清理。镜像 healthy 不能代替真实业务验收。根工作区 docs/DEPLOYMENT.md 保存共享基础设施说明，各仓库文档不包含生产密钥。
