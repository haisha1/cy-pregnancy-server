# Java 8代码阅读指南

## 目录和调用顺序

```text
src/main/java/com/chunyu/pregnancy
  PregnancyServerApplication  启动入口、扫描Mapper
  common                     跨业务公共能力
    result/ApiResponse       统一响应
    exception                业务异常、全局异常处理
    filter/RequestIdFilter   请求追踪ID
    ratelimit                Redis限流
    util/DigestUtils         只依赖JDK的散列工具
  entity                     AppUser、AuthSession：数据库实体
  dto
    request                  LoginRequest、RefreshRequest：请求参数与校验
    response                 TokenResponse、MeResponse：公开响应
  mapper                     AppUserMapper、AuthSessionMapper：SQL/CRUD
  service
    AuthService              账号业务接口，Controller依赖它
    SessionService           会话有效性查询服务
    impl/AuthServiceImpl     账号业务实现、事务和并发处理
  controller                 AuthController、CapabilitiesController：HTTP入口
  config                     配置绑定、Security装配、OpenAPI
  security                   TokenService、SessionValidityFilter：凭据与认证
  integration/wechat         微信网关接口
    impl                     WxJavaWechatGateway：微信SDK适配
src/main/resources
  application*.yml           公共/本机/云端配置
  db/migration               Flyway版本化SQL
src/test/java                默认单元测试、显式开启的MySQL集成测试
```

控制器处理“一次HTTP请求如何收发”；Service处理“业务步骤与原子性”；Mapper处理“如何读写数据库”。把它们分开后，修改表结构不会迫使页面理解SQL，也容易单独测试业务。

典型调用方向为`Controller → Service接口 → ServiceImpl → Mapper → MySQL`。Entity用于Mapper持久化，DTO用于接口收发，common被各层复用；它们不是一条依次执行的调用链。Controller不直接调用Mapper，也不直接返回Entity。

安全请求的补充分支为`SessionValidityFilter → SessionService → AuthSessionMapper`；微信外部调用为`AuthServiceImpl → WechatGateway → WxJavaWechatGateway`。配置类负责把组件装配起来，不放业务SQL。主业务服务提供接口和impl，单一用途的辅助服务可直接用具体类，不为每个工具机械增加空接口。

## 登录是怎样完成的

前端入口为app/cy-pregnancy/store/account.ts，启动只恢复缓存，档案内由用户显式登录。头像昵称的独立流程为AccountProfileController → AccountProfileService → WechatGateway/AppUserMapper：新code确认身份、昵称V2检查、AvatarImage重编码、revision条件更新。头像只供本人读取，不直接返回实体。详见[前后端联调说明](../../app/cy-pregnancy/docs/微信登录与服务端联调.md)。

1. RequestIdFilter生成服务端追踪ID。错误响应也带同一ID；不需要打印用户请求体定位问题。
2. SecurityConfig允许微信登录入口匿名访问。AuthController用Bean Validation校验DTO，Redis限流后调用Service。
3. WechatGateway用真实code换身份。网络调用在事务之外，避免等微信时占用MySQL锁。
4. AuthServiceImpl开启事务，根据AppID+身份散列创建或复用用户。数据库唯一键负责拦住并发重复创建。
5. 创建auth_session；只存refresh的散列。TokenService签JWT，响应在事务成功提交后返回。

后续`/me`请求先经Spring Security验签、有效期、issuer/audience校验，再由SessionValidityFilter查权威会话。只有身份属于该会话且账户可用才进入控制器。将来查档案还需额外检查该档案属于当前账户，不能把“已登录”等同“能访问任何UUID”。

## 三种容易混淆的对象

- 微信code：一次性登录材料，仅用于向微信换身份。
- accessToken：本系统签发的短期JWT，用来调用接口。
- refreshToken：本系统随机凭据，用来轮换会话凭据；不能直接调用业务接口。

JWT本身不保存服务端状态，所以还需数据库会话实现撤销。Redis当前只负责限流，不是身份和会话数据唯一存储。数据库故障时返回不可用，不允许跳过会话校验。

## 注解和常用写法

`@RestController`注册HTTP接口；`@Service`标识业务服务；构造器注入把依赖显式列出，避免到处new服务。`@Valid`触发请求校验；`@ConfigurationProperties`把YAML映射成类型明确的配置对象。

实体使用Lombok的`@Getter/@Setter`生成常规访问方法；没有用`@Data`给敏感实体生成默认toString，避免误打印令牌散列。DTO响应使用只读字段和构造方法。Java 8没有record、var、文本块，项目都用Java 8语法。

AuthService是业务接口，AuthServiceImpl是`@Service`实现，Spring通过构造器将实现注入Controller。AuthServiceImpl使用TransactionTemplate而非在私有方法上写`@Transactional`，便于看清事务起止。续期重放发现后先提交撤销，再在事务外抛401；若先抛异常触发回滚，撤销就会失效。Mapper里的`FOR UPDATE`需要处于事务中才有正确锁语义。

## 后续写代码时保持的约定

当前采用按技术层分包。新增档案、检查等功能时，把Controller放controller、服务契约放service、实现放service/impl、表实体放entity、入参/出参分别放dto/request和dto/response、数据库访问放mapper；业务增多后可在每层内加profile/examination等子包。字段注释解释单位、归属、版本和空值语义；方法注释解释目的和副作用；并发、授权、状态转换处写清原因。简单赋值不用逐行翻译。

健康数值用BigDecimal和十进制字符串API，日期用LocalDate，审计时间用Instant；不要照账号DTO把医学值改成double。禁止把实体或Pinia整个对象直接当公开响应。新增数据库变更用新迁移，新增能力经测试后再改capabilities。
